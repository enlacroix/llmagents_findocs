# Я, Ревизор

Сервис для проверки первичных финансовых документов. Загружаете скан счета, акта, договора или банковской выписки, сервис распознает текст, достает реквизиты и суммы, сверяет их со справочником контрагентов и либо одобряет документ, либо отправляет его бухгалтеру с пояснением, что не так.

Проект для курса по LLM-агентам. Идея, архитектура и результаты собраны в [презентации проекта](https://drive.google.com/file/d/1TNP6FLjyy-7y-FQ5iMkkqxYRJx7k2UEr/view).

## Какая модель и зачем

Мы используем DeepSeek API, модель `deepseek-flash`. Она умеет работать с картинками, отвечать в формате JSON и вызывать инструменты.

Модель делает три вещи:

- читает скан страницы, включая печати и рукописные пометки;
- раскладывает текст по полям нужного типа документа: стороны, реквизиты, позиции, итоги;
- проверяет результат: ищет спорные значения в тексте, сверяет контрагентов и решает, одобрить документ или отдать человеку.

Суммы, форматы реквизитов и сверку со справочником проверяет обычный код, а модель решает, что делать с найденными ошибками.

## Запуск

Нужны Docker и ключ DeepSeek API.

```bash
cp .env.example .env
```

Впишите ключ в `DEEPSEEK_API_KEY` в файле `.env` и запустите:

```bash
docker compose up --build
```

Интерфейс откроется на http://localhost:8000. Слева можно выбрать готовый скан из примеров или загрузить свой PDF.

Обработать все примеры из командной строки:

```bash
docker compose run --rm app python -m findocs corporative_docs/scans
```

Посчитать метрики качества:

```bash
docker compose run --rm app python -m findocs.evaluate
```

## Как это работает

Каждая страница проходит три шага: распознавание, извлечение полей по JSON-схеме и проверку. На проверке у агента есть пять инструментов: проверить поля, найти значение в распознанном тексте, сверить контрагента со справочником, одобрить документ или отправить его на доработку.

Что проверяем:

- форматы реквизитов: ИНН, КПП, ОГРН, расчетный счет;
- арифметику: строки, итоги, НДС, остатки по выписке;
- совпадение реквизитов контрагента со справочником.

Документ с ошибками или чужими реквизитами агент одобрить не может.

## Метрики

Качество считаем по эталонной разметке в `corporative_docs/keys`:

- доля правильно извлеченных полей;
- ошибки распознавания и ошибки разбора;
- выдуманные значения;
- доля документов, которые прошли без участия человека;
- сэкономленное время бухгалтера.
